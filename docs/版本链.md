## 2. 命令

| 场景 | 命令 | 说明 |
|---|---|---|
| 改完 UI | `powershell -File D:\work2\小厨-定稿\sync-page.ps1` | 同步全部节点 + 校验；**全 OK 才可继续** |
| 只校验 | `... sync-page.ps1 -VerifyOnly` | 不改任何文件 |
| 出货前 | `... sync-page.ps1 -CheckApk <apk路径>` | 校验 APK 内嵌页 == 链上版本（构建后必跑） |
| 发布到云 | `node D:\work2\小厨-定稿\publish.mjs <key>` | 默认发布链上定稿副本；成功自动写 `xiaochu-release\version.json` 发布记录 |

> 脚本会自动尝试 `npx cap copy`；首次使用前在本仓库根目录执行 `npm install`（一次性，装 @capacitor/cli），
> 未装时脚本自动"直接复制"并警告——**两种方式产物字节一致**，校验会兜底。

## 3. 铁律（防止回锅）

1. **只改唯一源**；链上其它任何文件**禁止手工编辑**（改完会被校验发现并覆盖）。
2. 每次改 UI 后**必须**跑 `sync-page.ps1`；校验非绿 = 禁止构建/发布（退出码 1）。
3. APK 出货前跑 `-CheckApk`（内嵌页 sha 必须 == 链上 sha）。
4. 服务器上的发布版本号由 `ui-publish` 递增（1.0.x），本地不手工维护；
   `xiaochu-release\version.json` 只读记录（publish.mjs 写），**不作为发布依据**。
5. 页面版本锚点：页内 `console.log('XIAOCHU cap 1.0')` 仅提示，版本以 sha256 为准。
6. **版本号事实源 = 仓库根 `VERSIONS.json`**（规范见 `docs\版本规范.md`）：
   `chainSha256/chainSize` 由本脚本自动维护，`server.*` 由 publish.mjs 自动维护，均禁止手工编辑。
