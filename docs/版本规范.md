## 1. 方案（一句话）

**APK = 语义化三段式（versionName）+ 单调递增 versionCode；UI 页面 = 服务端 ui_releases 序列（1.0.x），两者在 VERSIONS.json 中映射对齐。**

| 维度 | 规则 | 现状 |
|---|---|---|
| APK versionName | `主.次.修订`（semver）；v1.0 历史即 `1.0.0` | 下一构建 **1.1.0** |
| APK versionCode | 每构建 +1，只增不减（安装覆盖判断依据） | 下一构建 **4** |
| UI 页面版本 | 服务端 `ui-publish` 自动递增（1.0.2→1.0.16→**1.0.17**），**不与 APK 解耦强绑** | 最新 **1.0.17**（=链上活稿，已覆盖实验代码 1.0.16） |
| 契约 | `contract=1`（页面↔桥数据结构契约，变契约须随 APK 发版） | 1 |
| 链上页面 | sha256 全等（唯一源 4BEE6F4C… 84KB） | `VERSIONS.json.chainSha256` |

## 2. 改版本的三处（缺一不可）

1. `android/app/build.gradle.kts` → `versionCode` / `versionName`
2. `VERSIONS.json` → `appVersion` / `versionCode`
3. 本文件 §5 历史表追加一行（或发布说明）

> `VERSIONS.json` 的 `chainSha256/chainSize` 由 `sync-page.ps1` 自动维护；`server.*` 由 `publish.mjs` 自动维护。
